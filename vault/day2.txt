# Day 2 - SQL beyond the local machine

## Core message

> **The platform changes. The SQL thinking travels with you.**

This is the confidence-building day. They are not becoming cloud specialists. They are seeing that SQL, structured data, tables, filters, joins and aggregations still make sense outside SSMS.

---

## Day outcome

By the end of Day 2, learners can say:

> “I have used SQL in more than one cloud-style environment, and I can explain what stayed the same and what changed.”

---

# Day structure

## 09:30 - 09:45 - Opening frame

Start with the learner comment from today:

> Today is not about turning you into cloud engineers.
> It is about expanding where you think SQL and data analysis can happen.

Then:

> Yesterday the database was local.
> Today the data is somewhere else.
> Let’s see how much actually changes.

Ask them:

> What do you think will be different?

Capture answers briefly.

Likely answers:

* login/access
* browser-based tools
* finding the data
* different interface
* permissions
* maybe different SQL
* sharing outputs
* not knowing where the server is

Then reassure:

> Good. Most of those are around the SQL. The SQL itself should still feel familiar.

---

## 09:45 - 10:10 - The transfer model

Use a simple model:

```text
Local machine / SSMS
        ↓
Cloud analytics platform
        ↓
SQL query
        ↓
Result set
        ↓
Analysis / visual / decision
```

Then the key comparison:

| What stays familiar  | What changes               |
| -------------------- | -------------------------- |
| tables               | location                   |
| rows and columns     | access                     |
| data types           | interface                  |
| SELECT               | permissions                |
| WHERE                | scale                      |
| JOIN                 | sharing                    |
| GROUP BY             | cost/performance awareness |
| analytical questions | organisational context     |

The teaching point:

> We are not throwing yesterday away. We are carrying it forward.

---

## 10:10 - 10:40 - First cloud context: Google BigQuery

Keep this very contained.

The question is not:

> How does all of Google Cloud work?

The question is:

> **Can I find structured data and query it with SQL?**

Learners only need to notice:

* there is a cloud environment
* data is organised into projects/datasets/tables
* there is a SQL editor
* query results appear in a grid
* SQL still works

Possible trainer line:

> For today, BigQuery is just our first example of SQL beyond the local machine.”

---

## 11:00 - 12:10 - BigQuery SQL practice

Use familiar SQL. Do not make the SQL hard yet.

Suggested sequence:

### 1. Look at rows

```sql
SELECT *
FROM table_name
LIMIT 10;
```

Question:

> “What can we tell about this table just by looking?”

---

### 2. Select specific columns

```sql
SELECT
  order_id,
  order_date,
  region,
  total_amount
FROM table_name
LIMIT 20;
```

Question:

> “Which columns look useful for analysis?”

---

### 3. Filter

```sql
SELECT *
FROM table_name
WHERE region = 'North';
```

Question:

> “What does the WHERE clause do here?”

---

### 4. Summarise

```sql
SELECT
  region,
  COUNT(*) AS number_of_orders
FROM table_name
GROUP BY region
ORDER BY number_of_orders DESC;
```

Question:

> “What business question does this answer?”

---

### 5. Optional join

Only if the data is ready and the learners are comfortable.

```sql
SELECT
  o.order_id,
  o.order_date,
  p.product_name,
  p.category,
  o.quantity
FROM orders o
JOIN products p
  ON o.product_id = p.product_id;
```

Question:

> “Why did we need two tables?”

This quietly points toward Day 3.

---

## 12:10 - 12:20 - Before lunch reflection

Ask them to complete this:

| Prompt                                           | Learner note |
| ------------------------------------------------ | ------------ |
| One thing that felt familiar                     |              |
| One thing that felt different                    |              |
| One thing I was less worried about than expected |              |

This is important. It locks in the confidence point.

# Afternoon - Fabric / SQL to visual

## 13:20 - 13:35 - Bridge from Google to Fabric

Say:

> “This morning we used SQL in one cloud analytics platform. This afternoon we use a different environment to show the same transfer. The point is not the brand. The point is that your SQL and analysis thinking travels.”

Then connect to their previous Power BI module:

> “You have already seen that analysts often need to turn data into visuals. So now we look at how a SQL result can become something reportable.”

---

## 13:35 - 14:15 - Query for a reportable result

Use a simple summary query.

For example:

```sql
SELECT
  region,
  SUM(total_amount) AS total_sales,
  COUNT(*) AS number_of_orders
FROM sales
GROUP BY region
ORDER BY total_sales DESC;
```

Ask:

> “Is this still row-level data, or has it become analysis?”

That distinction matters.

Then:

> “Would this be useful as a table in a report?”

---

## 14:15 - 14:45 - Visualise the result

The goal is not a complex report.

The goal is:

> **SQL result → visual answer**

A simple report could have:

* sales by region
* number of orders by status
* sales by product category
* table of top products

Keep it small.

Suggested learner task:

> “Create one visual that answers one question from the SQL result.”

Questions could be:

* Which region has the highest sales?
* Which product category performs best?
* Which status appears most often?
* Which month has the most orders?

---

## 15:00 - 15:35 - Compare the three environments

Bring back the comparison table.

| Environment       | Where is the data?                           | How do I query it? | What feels familiar?          | What is different?                      |
| ----------------- | -------------------------------------------- | ------------------ | ----------------------------- | --------------------------------------- |
| Local / SSMS      | local database                               | SQL editor         | tables, SELECT, WHERE, JOIN   | installed locally                       |
| BigQuery          | cloud dataset/table                          | browser SQL editor | SQL still queries tables      | project/dataset structure, cloud access |
| Fabric / Power BI | workspace/lakehouse/warehouse/reporting area | SQL/report tools   | query results become analysis | closer to reporting and sharing         |

They can fill this in individually first, then discuss.

---

## 15:35 - 15:55 - Close discussion

Use this question:

> “If your organisation moved data from one platform to another, what knowledge would still help you?”

Expected answers:

* understanding tables
* knowing SQL
* knowing joins
* checking data types
* asking good questions
* understanding relationships
* knowing when to group/aggregate
* checking results

Then final point:

> **“You are not starting again every time the tool changes.”**
